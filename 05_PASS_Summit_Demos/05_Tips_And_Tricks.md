# 5. Tips and Tricks

This section is the presenter playbook for making the demos smooth, understandable, and repeatable.

## How to create this into your own workflow

1. Keep one repository as your source template.
2. Use issue forms to enforce complete requests.
3. Add guardrail automation before adding advanced CI.
4. Use service containers so demos do not depend on personal environments.
5. Keep documentation close to code (wiki, Mermaid, gist snippets).

## Why these tips matter

Live demos usually fail because of hidden dependencies, missing data, or unclear process. These tips remove those failure modes.

## How to use these tips during the PASS session

1. Start with a change request issue and show required fields.
2. Open a PR and walk through the PR template.
3. Show automated pass/fail behavior from workflows.
4. Trigger an event workflow and explain runner/secrets output.
5. Close by showing where runbooks and checklists live.

## What a database professional gains

- Stronger change governance with less manual policing.
- Faster feedback loops on risky SQL.
- Better production readiness and rollback discipline.
- Reusable standards that scale to multiple teams.

## High-value presenter shortcuts

| Tip | Why it works for DBA audiences |
| --- | --- |
| Keep one intentional failure case ready | Demonstrates value of automation instantly |
| Use checklist-based templates | Aligns with change-control culture |
| Show rollback before deployment | Reinforces reliability-first mindset |
| Prefer one command demos | Reduces live typing mistakes |
| Capture everything in issues/PRs | Improves auditability and postmortems |

# 08_Tips_and_Tricks

Use this as the presenter runbook for clean, repeatable demos.

## How to create this into your own workflow

1. Keep one template repo with all controls pre-wired.
2. Start every change with issue forms.
3. Keep approval + automation checks mandatory.
4. Demo one passing and one failing SQL change every time.
5. Keep docs close to code (wiki, Mermaid, gist).

## Why these tips matter

Most live failures come from missing setup details, not from core concepts.

## How to use these tips

1. Follow the directory order exactly.
2. Use short commands from each section README.
3. Narrate risk, rollback, and validation at every step.

## What a database professional gains

- Repeatable governance demos.
- Better change-control habits.
- Faster incident communication.
- Stronger trust in automation gates.

## High-value shortcuts

| Tip | Why it works |
| --- | --- |
| Keep one intentional failure case ready | Shows the value of controls immediately |
| Show rollback before merge | Reinforces reliability-first behavior |
| Use one-command script examples | Reduces live demo errors |
| Keep evidence in issues and PRs | Improves compliance and audit readiness |
